# 02 现代类比与可行性评估

## 1. 与现代低端 MCU 的对照

### 1.1 相似的部分（资源画像）

| 维度 | 共同点 |
|---|---|
| 内存规模 | 几 KB 级，无外存管理 |
| 数值模型 | 整数/定点，通常无浮点单元 |
| 存储管理 | 无 MMU、无虚存，扁平地址 |
| 运行形态 | 裸机、轮询外设、单用途 |

### 1.2 不相似的部分（控制流底座）

| 维度 | 现代低端 MCU（Cortex-M0+/AVR/PIC） | 103 机 |
|---|---|---|
| 栈指针 / 栈 | 有 SP，硬件栈帧 | 无栈、无 SP |
| 调用/返回 | 有 CALL/RET（或 RCALL/RET） | 无 call/return，只有转移 |
| 中断向量 / 中断控制器 | 有 NVIC / 向量表 | 无中断，轮询握手 |
| 定时器 | 有 SysTick/定时器，可产生节拍 | 无定时器 |
| 寻址/操作 | 字节/位寻址，位操作指令 | 按 31 位字寻址，仅逻辑乘 |
| 程序载入 | Flash 上电自举 | 面板/纸带手工装入 |

**结论：103 的"身材"像 MCU，"控制流硬件"停留在 MCU 之前一代。**

## 2. 高级语言适配

### 2.1 历史事实

103 当年只跑机器码；无汇编语言层，更无高级语言（复旦 103 回忆资料可互证）。

### 2.2 推演：最适配的语言子集

**Fortran II 风格的静态定点科学计算子集**，约束：

- 静态分配全部变量与数组，无堆；
- 无递归、无动态调用；
- GOTO 为主的控制流；
- 一维静态数组；
- 静态调用约定（若未来补 CALL/RET）。

### 2.3 不适配的语言范式

| 范式 | 原因 |
|---|---|
| LISP | 动态堆、递归、链表/指针，无栈无堆 |
| Forth | 依赖栈与字典编译机制 |
| BASIC 解释型 | 解释器常驻 + 字符串/动态存储，规模与机制均不足 |
| Java / Python 等 | 虚拟机、堆、自动内存管理、递归，完全不匹配 |

## 3. 操作系统 / 调度可行性结论

| 目标 | 原生可行性 | 主要卡点 |
|---|---|---|
| 批处理算题 / 监控装入器 | 可行 | —— |
| 协作式静态调度雏形 | 勉强可做（玩具级） | 无栈、无定时节拍，2048 字规模紧张 |
| 抢占式 RTOS | 不可行 | 任务栈/栈指针、中断/tick、上下文切换 |
| DOS / CP/M 类磁盘 OS | 不可行 | 磁盘文件系统、栈/调用、内存规模（CP/M 最小 16 KiB RAM、内核约 6 KB、需软盘） |
| UNIX / UNIX-like | 不可行 | 上述全部 + 多用户/保护/分时；V1 UNIX 内核即占约 16 KB，103 全部内存约 7.75 KiB |

### 3.1 RTOS 需求分层对照

| RTOS 必备 | 103 现状 |
|---|---|
| 任务栈（每任务独立栈帧） | 无栈、无 SP；子程序只能静态约定，不可重入 |
| 上下文切换（保存/恢复寄存器） | A/B/C/PC 可静态存固定内存槽，理论可行，无硬件压栈配合 |
| 定时器节拍（周期性 tick） | 无定时器、无中断，无法产生系统节拍 |
| 中断（外设事件/时钟打断） | 无中断机制，I/O 全轮询 |
| 内核服务调用 + 返回 | 无 call/ret，系统服务只能静态跳转 |
| 调度器 / TCB / 同步原语 | 固定任务数、静态 TCB 可模拟；动态队列无堆支持 |

### 3.2 三档可行性

1. **超级循环（superloop）裸机程序**：可行。主循环依次轮询静态任务，共享静态变量，无内核；严格说不是 RTOS。
2. **协作式静态调度雏形**：勉强。固定静态任务、静态上下文槽、任务主动让出；无抢占、无定时节拍、不可重入；规模紧张，属调度思想演示。
3. **抢占式 RTOS**：原生不可行。硬性缺失任务栈与栈指针、中断/tick、上下文切换、可重入调用约定。

### 3.3 若在软核上补出 RTOS 能力所需

1. 栈指针 + 压栈/出栈 + CALL/RET；
2. 定时器 + 中断控制器；
3. 上下文切换通路（异常入口保存寄存器、调度选任务、恢复上下文）；
4. 索引/地址运算能力；
5. 内存扩到几 KB 以上，分内核区与任务栈区。

补完后得到的是现代小 MCU 风格核，103 只保留定点双地址外观；现成 FreeRTOS 等仍不能直接跑，内核需为该核重写。

## 4. 与前序判断的串联

- 103 像的是 MCU 的"资源受限外形"，不是"控制流底座"；
- RTOS 需求集中在底座（栈、调用、中断、节拍），103 缺的正是这些；
- 因此原生最多做到前后台轮询与玩具级协作调度，离现代 RTOS 差的不是内存大小，而是任务切换与中断机制。
