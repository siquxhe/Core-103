# 06 协作式固件方案

> 路线决策：在"协作式 / 抢占式"之间选定**保持协作式、把这套做扎实**。本方案是常驻固件 + 静态多任务调度的设计设想，内核 ISA 不改。

## 1. 方案三层

```
控制台固件（常驻 ROM）
  ├─ 命令接收 / 状态显示
  ├─ 装载器：调用硬件拷贝引擎把任务镜像装入 RAM
  └─ 调度器 dispatcher：静态任务表轮询切换
硬件拷贝引擎（外设，见 07 文档）
RAM 任务区：各任务镜像 + 静态上下文块
```

## 2. 常驻控制台

| 要求 | 形态 | 判定 |
|---|---|---|
| 上电常驻、不被任务覆盖 | 软核地址空间分 ROM 控制台区 + RAM 任务区；原生 103 无 ROM 概念，需软核添加 | 软核可行 |
| 命令接收、状态显示 | 复用现有 I/O 握手（07 输入 / 45 输出），轮询 | 可行 |
| 驻留内存保护 | 无保护机制，靠链接约定：任务镜像不得覆盖控制台区 | 约定可行，无硬件强制 |

## 3. 装载阶段

- 控制台维护任务目录（镜像 ID、装载原点、字数、入口）。
- 经硬件拷贝引擎按块装入 RAM 任务区（协议与 FSM 见 `07-硬件拷贝引擎设计.md`）。
- 任务镜像按**固定装载原点**链接，绝对地址原样落位；ISA 无重定位基础。

## 4. 协作式调度模型

### 4.1 每任务静态上下文块

可见架构状态：PC、A、B、C（Д 为加法器占位）。为每个任务在 RAM 开固定槽：

```
任务 i 上下文块:
  saved_PC
  saved_A
  saved_B
  saved_C
  状态(就绪/挂起)
  入口地址
```

### 4.2 dispatcher 动作

1. 保存当前任务：A/B/C/当前 PC 存入其上下文槽（05/15 系列传送）；
2. 按静态任务表取下一个就绪任务；
3. 恢复它的 A/B/C/PC；
4. 跳转到 saved_PC（转移指令 `24`，注意其同时把 B 写入 c2，需按语义安排）。

### 4.3 任务协议

- 任务入口由装载器/汇编侧统一登记；
- 任务在约定让出点跳回 dispatcher（yield）；
- 任务变量全静态分配；共享子程序不可重入；禁止递归。

## 5. 硬约束（本档必须遵守）

- **协作式，无抢占**：无定时器中断，任务必须主动让出；死循环任务会占死整机。所谓"分时"是轮流让步，不是时间片轮转。
- **无栈、不可重入**：无任务栈，无嵌套子程序；任务间共享数据走静态缓冲区 + 约定。
- **无阻塞原语硬件支撑**：最简信号量计数器可在静态内存实现；任务等 I/O 时在轮询点自检状态。
- **规模紧张**：控制台 + 装载器 + dispatcher + N 个任务镜像 + 上下文块全压在 2048 字内，两三个小任务即到天花板；软核目标应扩 RAM 到 8–32 KiB，2048 字仅作兼容仿真模式。

## 6. 架构谱系定位

| 形态 | 中断 | 栈 | 抢占 | 本方案位置 |
|---|---|---|---|---|
| 裸机 superloop | 无 | 无 | 无 | 单任务时等同 |
| **协作式多任务监控/执行器** | 无 | 无（静态槽） | 无 | **本方案落点** |
| 抢占式 RTOS | 有（tick + ISR） | 有任务栈 | 有 | 不可达 |
| 磁盘 OS / UNIX | 有 | 有 | 有 + 文件系统/保护 | 不可达 |

历史对照：相当于早期小型机上的驻留监控 + 任务依次装入水平；比裸机强在常驻调度、多任务静态轮转，比真 RTOS 缺定时器中断和栈切换。

## 7. 本档不做清单

- 不做中断驱动的 DMA；装载由核心主动发起、轮询等待完成；
- 不做并发读写；引擎搬运期间核心停在装载点，避免双主争用内存；
- 不改内核译码/节拍/指令集；
- 不做任务栈、不做抢占；上下文只用静态保存槽。

## 8. 升级到抢占式所需（另立一档，不在本方案内）

1. 定时器 + 中断控制器 + 中断入口；
2. 栈指针 + 每任务栈 + CALL/RET；
3. 中断上下文保存/恢复通路；
4. 调度器按 tick 抢占切换。
