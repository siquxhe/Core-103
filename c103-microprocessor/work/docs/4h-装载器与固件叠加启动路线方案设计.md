# 4h · 装载器 + 固件叠加启动路线方案设计

> 范围：在 4g（引擎子系统装配综合、背靠背加压、dbg 量产移除）之后，界定"装载器写镜像就位 + 固件运行期发命令块"两条通路叠加的实现路线。
> 本文为方案设计（选型 / 切分 / 接口 / 分层落地），尚未写对应 RTL；所列事实均来自当前正本源码与既有 testbench 第一手核对。
> 关联文档：4e（命令块剥离本地寄存器与回归）、4f（镜像目录与校验链路）、4g（装配综合与加压、dbg 量产边界）。

## 一、路线定位

### 1.1 两条写通路的定义

| 通路 | 发起主体 | 所处阶段 | 写入对象 | 数据来源 | 是否依赖核心运行 |
|---|---|---|---|---|---|
| 装载器写（loader） | `image_loader`（路线 A 仿真模型；路线 B 上板为 SPI/NOR 引导） | 复位后、核心启动前，核心停住 | 程序段 / 常量段 / 数据介质，按段落主存 | 打包器 `image-pack` 产出的结构化镜像（目录头 + 段表 + 镜像体 + 校验尾） | 不依赖 |
| 固件写（firmware） | 核心 PU 执行的固件搬运子程序 | 核心已取指运行后的运行期 | 命令块 `SRC/DST/LEN/GO`，完成后写 `ACK` | 固件运行期配置 / 常量区预存参数 | 强依赖：核心必须能执行内存传送指令与轮询循环 |

### 1.2 叠加而非二选一

**装载器负责把镜像就位，固件负责后续运行期的搬运命令。** 两者在启动时序上前后衔接，不并发写同一对象：

- 装载期：核心停住，`image_loader` 清场、灌各段、复核校验和，给出入口 PC；此阶段引擎未启动，无命令块写入。
- 运行期：核心从入口取指，固件逐段发命令块、轮询完成、握手 ACK、回 IDLE，背靠背服务后续段。

### 1.3 与既有验证链路的差异

既有 `tb_fw_poll.v` 的编排是：testbench 经纸带 5-bit 符号流（内核 IO 译码 → 内存写）代写命令块 `SRC/DST/LEN/GO`，固件只做"轮询 DONE → 写 ACK"。本路线把**发命令块**这一动作也收归固件：固件经 PU 内存传送指令直接写命令块，testbench 不再代写参数。

## 二、已核事实（第一手源码）

### 2.1 `image_loader` 现状（`rtl/image_loader.v`）

- 参数 `WORDS=2048`；端口：`clk/resetn`；装载写口 `loader_wr_en/loader_wr_addr[11:0]/loader_wr_data[30:0]`；状态 `loader_done/loader_err/loader_err_code[3:0]/loader_entry[11:0]`。
- FSM：`IDLE → CHECK → WIPE → LOAD → DONE/ERROR`。
  - `CHECK`：魔数 `32'h103103`、版本/算法、段数、入口越界、段类型、段字数、目的越界、偏移越界、校验和、字数与段表一致性复核（错误码 1..11）。
  - `WIPE`：**清零整个主存地址空间（含命令块 2400..2407）**。
  - `LOAD`：按段表 `seg_dst + seg_k` 写镜像体；`DONE` 锁存 `entry_pc` 到 `loader_entry`。
- **当前只装载程序段 / 常量段 / 数据段镜像，不写命令块。**
- 路线 B 预留：上板时把内部 `$readmemh` 文本源替换为 SPI NOR 控制器读回字流；解析、段表、校验口径两侧共用（见 4f §5.3）。

### 2.2 命令块布局（八进制地址，31 位字）

| 地址 | 符号 | 含义 | 写主 |
|---|---|---|---|
| `2400` | `SRC` | 搬运源地址 | 固件（PU 写） |
| `2401` | `DST` | 搬运目的地址 | 固件（PU 写） |
| `2402` | `LEN` | 字数 | 固件（PU 写） |
| `2403` | `GO` | 启动位（ctrl 装配后由引擎消费，自清） | 固件（PU 写） |
| `2404` | `BUSY` | 忙状态镜像 | ctrl 回写 |
| `2405` | `DONE` | 完成状态镜像 | ctrl 回写 |
| `2406` | `ERR` | 错误状态镜像 | ctrl 回写 |
| `2407` | `ACK` | 固件回执握手位 | 固件（PU 写） |

### 2.3 内存写通路与命令块旁路（`ip_core/core/memory.v`）

- 功能写请求：`do_mem_write = mem_write_from_io || mem_write_from_pnl`（IO 输入设备写 / PU 写）。
- CPU 写主经写仲裁器产出 `ram_wr_req/ram_wr_addr/ram_wr_data`，与引擎子系统写主（搬运写 + ctrl 状态写）排队轮转、满队背压。
- 命令块写旁路：

  ```verilog
  wire cmd_hit_addr = (cmd_w_addr >= 12'o2400) && (cmd_w_addr <= 12'o2407);
  assign cmd_wr_en   = (ram_wr_req || dbg_wr_en) && cmd_hit_addr;
  ```

  即**功能写（经仲裁器）或仿真 dbg 写命中 2400..2407 时**，透传 `cmd_wr_*` 到 `engine_ctrl.local_wr_*` 同步本地命令块寄存器；主存同时留一份副本供 CPU 轮询。PU 写命令块同样走 `ram_wr_req`，命中后旁路成立。

### 2.4 固件写命令块的指令集可行性

- `05/15`（Пч 传送）：`M[c1] → M[c2]`，留存 AU 第二数寄存器，是 PU 写内存路径（见指令集兼容性核对 §4）。
- 既有固件程序已用 `05` 传送写 ACK：`0004 +05 2001 2407`（`M[2001] → M[2407]`）。
- 结论：**固件可以把预存于常量区的参数值，用 `05` 传送到 `2400/2401/2402/2403`**，完成命令块下发；指令集与写通路均已具备，无需新增译码指令。

### 2.5 入口 PC 现状（`core/start_reg.v`，ПР 启动寄存器）

- 复位时 `reg_start <= 0`（复位取指地址固定 `0000`）。
- 三条更新通路：面板 `do_arr_strt` 预置（`arr_strt_data_from_pnl`）；PU 递增；跳转 `do_sel_to_strt` 装载 `sel_value`。
- **没有独立的"复位加载 entry"硬件通路**；面板 `arr_strt` 预置通道是现成的启动地址写入口。

### 2.6 既有 `tb_fw_poll` 三段编排（参照基线）

| 轮次 | 源 → 目的 | 长度 | 握手 |
|---|---|---:|---|
| 1 程序段 | `1200 → 0000` | 6 字 | drain 回 IDLE |
| 2 常量段 | `1600 → 2000` | 3 字 | drain 回 IDLE |
| 3 数据段 | `1500 → 3000` | 3 字 | 不 drain；DONE 保持 1，供随后启动的固件轮询 |

固件子程序（目的区 6 字）：读 `DONE(2405)` → 减法判符号 → 条件跳转循环 → 写 `ACK(2407)` → 停机。

## 三、推荐架构与职责切分

### 3.1 职责表

| 阶段 | 主体 | 动作 | 通路 / 信号 |
|---|---|---|---|
| 复位清场 | `image_loader` | `WIPE` 清主存；`LOAD` 按段灌程序/常量/数据介质；`CHECK` 复核段表与校验和 | 装载写口（仿真 dbg 口；量产路线 B 接仲裁 CPU 写主） |
| 装载完成 | `image_loader` | 置 `loader_done`；置 `loader_err/err_code`；锁存 `loader_entry` | 顶层启动联锁 |
| 启动联锁 | 顶层 / testbench | `loader_done=1 且 loader_err=0` 才允许释放核心；先把 `loader_entry` 经面板 `arr_strt` 预置进 `start_reg` | `core_resetn` 门控 + `pnl_do_arr_strt / pnl_arr_strt_value` |
| 运行期搬运 | 固件子程序 | 逐段：参数值 `05` 传送到 `2400..2403` → 轮询 `2405 DONE` → 校验目的区 → `05` 写 `2407 ACK` → 等 ctrl 自清、引擎回 IDLE → 下一段 | PU 写内存 → 命令块旁路 → `engine_ctrl` → `copy_engine` |

### 3.2 核心原则

1. **loader 不碰命令块。** 命令块是与引擎 FSM 强耦合的运行期状态机（GO 自清、BUSY/DONE/ERR 镜像、ACK 握手）；装载期核心停住，由 loader 发 GO 会打乱启动时序与后续命令衔接。
2. **命令块单一写主。** 运行期命令块只由固件经 PU 写口写入；不在装载器侧另开命令块写入口，避免双主写命令块的仲裁与竞争。
3. **装载期与运行期不并发。** loader 写在核心停住阶段完成，与引擎搬运写、ctrl 状态写天然错开，复用既有 CPU 写主队列即可，**不扩第三写主**。

## 四、启动时序

```
resetn ──► loader: WIPE ──► LOAD(各段) ──► CHECK/校验 ──► loader_done=1
                                                              │
                                       loader_err=0 门控 ─────┤
                                                              ▼
                                        预置 start_reg = loader_entry
                                        (面板 arr_strt 通路)
                                                              │
                                                              ▼
                                              释放核心复位, 固件取指
                                                              │
                  固件: 05 SRC→2400, DST→2401, LEN→2402, GO→2403
                                                              │
                                                  ctrl 装配, 引擎搬运
                                                              │
                                       轮询 2405 DONE=1 ──► 校验目的区
                                                              │
                                              05 写 2407 ACK ──► ctrl 自清
                                                              │
                                                  引擎回 IDLE, 镜像自清
                                                              │
                                                         下一段（背靠背）
```

**时序约束**

- 固件首个 `issue` 必须晚于 `loader_done`；装载未完成、校验失败时核心不允许启动。
- `WIPE` 会清掉命令块八字；首轮搬运前 `BUSY/DONE/ERR/ACK` 状态镜像由 ctrl/固件初始化为零（既有 `tb_fw_poll` 启动段即先清零 2404..2407）。
- 一段未 drain（ctrl 停在 `S_DONE` 等 ACK）前，不得发下一条 GO。

## 五、接口改动清单（相对现状）

| # | 改动点 | 现状 | 叠加路线目标 | 首版口径 |
|---|---|---|---|---|
| 1 | 启动联锁 | `core_resetn` 单独脉冲；loader 未进装配顶层 | `loader_done/loader_err` 作为核心复位释放门控；`loader_entry` 接入启动地址预置 | 仿真 tb 层连线；不改 PU 译码 |

| 3 | loader 写口 | 仿真接 memory dbg 口 | 量产/综合形态改接仲裁 CPU 写主；dbg 口 tie 0（对齐 4g 变体口径） | 路线 B 预留，本轮不改解析/校验逻辑 |

## 六、分阶段落地

| 层级 | 目标 | 现状 | 下一步 |
|---|---|---|---|
| L1 装载单元 | loader 解析 / 校验 / entry / 报错码分支 | 已有回归：`tb_image_loader`（正向）+ `tb_image_loader_err`（报错码），21/0 PASS | 维持，不回退 |
| L2 装配子系统 | 引擎 + ctrl + 仲裁 + memory 背靠背加压，不依赖核心 | 4g 已落：`tb_engine_backpressure`，PASS=154/FAIL=0；综合资源正本/副本一致 | 维持基线 |
| **L3 端到端** | loader 灌镜像 → 联锁 → 核心启动 → 固件发命令块背靠背搬运握手 | 未建；`tb_fw_poll` 是 tb 代写命令块的参照基线 | 先搭骨架：loader 替代 dbg_fill 预填介质段；联锁门控；固件 05 发命令块 / 轮询 / ACK；再补逐字比对判据 |
| L4 量产综合形态 | 剥离 dbg，loader 写口接仲裁；整链路综合资源复核 | 4g 已出引擎子系统口径；整核综合基线口径不同不可混比 | 待 L3 仿真闭环后，按综合变体目录切形态复核 |

### 6.1 L3 端到端 tb 骨架要点

1. **镜像来源**：由 `image-pack` 生成结构化 `case.hex`（程序段 / 常量段 / 数据段 + 入口 PC），loader 经 dbg 口灌入；不再用 `dbg_fill` 逐字预填介质源区。
2. **联锁**：`wait(loader_done || loader_err)`；`loader_err` 非零即判失败并打印 `err_code`；成功后驱动 `arr_strt` 预置入口，再释放 `core_resetn`。
3. **固件程序段**：编排搬运子程序——常量区预存各段 `src/dst/len` 与 GO=1；固件循环取段参数、`05` 写命令块、轮询 `DONE`、校验目的区、写 `ACK`、回 IDLE 后进入下一段。
4. **判据**：各段目的区逐字落位（与镜像快照比对）；末段 DONE 镜像=1；核心停机；引擎回 IDLE；ACK/DONE 镜像自清。
5. **护栏**：轮询 / 等待 ACK 加超时护栏，超时记 FAIL 并打印引擎 `state/remain/err_code`，避免死循环挂住仿真。

## 七、取舍、风险与待核项

### 7.1 entry 装载的两条路径

- **首版（推荐）**：复用面板 `arr_strt` 预置 `start_reg`，不改 PU 译码；与 M-3 面板"装起始地址再启动"的操作习惯一致。
- **可选改造**：若要求纯硬件上电自举、不经面板预置，需在 `start_reg` 复位分支增加 `entry_load` 旁路（复位时装入外部 entry）。该项改动触及核心取指链，留待 L3 跑通面板预置后再评估。

### 7.2 loader 不发首条命令的代价

固定布局的"上电即搬"也要等固件跑起来发首条命令；若后续出现纯硬件自举搬运需求，再单独评估 loader 下发首条命令的可选通路。**该通路不进首版**，避免命令块双写主。

### 7.3 已知风险

- **并发争写定向用例缺口**：CPU 写与引擎写同拍并发的定向加压用例尚未补充（4g 背靠背主要覆盖引擎侧背靠背与边界错误）；L3 后需补一条 CPU/eng 同拍争写用例。
- **时序口径**：4g Fmax 55.404 MHz 为综合估算，真实时序以布局布线为准；当前无开发板，未跑 P&R。
- **镜像段表与命令块参数的对应**：多段搬运的 `src/dst/len` 由固件逐段提供；镜像段表描述的是"装载就位"布局，运行期搬运命令是另一组参数，两者不要混用（4f §段表口径）。

### 7.4 待核项（进入 L3 前确认）

- 核心 PU 写命令块区间（2400..2407）时，`mem_write_from_pnl` 锁存的地址/数据与 `ram_wr` 旁路对齐拍数；L3 首跑以 VCD/波形核对 GO 命中 ctrl 本地寄存器的时序。
- 固件子程序在目的区的地址编排（常量区暂存、跳转目标）需避开命令块与被搬运段的地址重叠。
