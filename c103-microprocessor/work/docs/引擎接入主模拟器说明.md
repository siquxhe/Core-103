# 拷贝引擎接入主模拟器 · 接入说明（第一步落地）

> 日期：2026-11-24 ｜ 对应 07 文档落地顺序第 1 步：C 模拟器侧跑通装载协议与数据通路。
> 边界：不改内核译码、节拍与指令集；引擎为外挂外设，核心通路保持原 103 行为。

## 1. 接入目标

把阶段一独立验证的拷贝引擎 FSM 接到 103 C 模拟器的同一内存上，软件侧跑通：

```
核心下发 src/dst/len + go  →  引擎独占搬运  →  done/err 握手  →  核心继续
```

本阶段只验证**装载协议与数据落位**；"核心执行装入的任务代码"留到下一阶段。

## 2. 接入架构

```
                ┌─────────────────────────────┐
                │  103 C 模拟器 (103.c)        │
                │  machine_mem[4096] 扁平内存   │
                └───────────────▲─────────────┘
                                │ 绑定同一数组（非副本）
                ┌───────────────┴─────────────┐
                │  engine_bridge（接入桥）       │
                │  - 命令/状态寄存器透传         │
                │  - 轮询驱动 FSM 一拍          │
                └───────────────▲─────────────┘
                                │
                ┌───────────────┴─────────────┐
                │  copy_engine（7 态 FSM）      │
                │  IDLE/ARM/FETCH/WRITE/CHECK  │
                │  DONE/ERR                    │
                └─────────────────────────────┘
```

- 引擎源区与目的区同属模拟器扁平内存（镜像源区 / 任务目的区按地址约定划分）。
- `num_t`（`unsigned int`）与引擎 `uint32_t` 位宽一致，接入桥直接强转绑定，不做内存拷贝副本。
- 模拟器仅向桥接层暴露 `machine_mem`（`103.h` 补 `extern num_t *machine_mem;` 与自包含 `stdio.h`）；内核源码逻辑零改动。

## 3. 装载协议时序

| 步骤 | 动作 | 桥接 API |
|---|---|---|
| 1 | 绑定模拟器内存 | `eng_bridge_init()` → `eng_bridge_bind_sim_memory()` |
| 2 | 核心写命令寄存器：源地址、目的地址、长度，发 go | `eng_bridge_load(src, dst, len)` |
| 3 | 核心轮询 busy；桥接每拍推进一步 FSM | `eng_bridge_poll()` / `eng_bridge_busy()` |
| 4 | 搬运完成：`done=1`，或失败：`err=1` + `err_code` | `eng_bridge_done()` / `eng_bridge_err()` / `eng_bridge_err_code()` |
| 5 | 核心握手清除，引擎回 IDLE，可复装 | `eng_bridge_ack_done()` / `eng_bridge_ack_err()` |

错误码沿用原型：`CE_ERR_SRC_OOB`（源越界）、`CE_ERR_DST_OOB`（目的越界）、`CE_ERR_ZERO_LEN`（零长度）。

## 7. 遗留与下一步

1. **指令级触发**：当前装载由测试驱动直接调桥接 API；真实链路需定义核心如何经输出口串行下发 `src/dst/len/go`（复用 5-bit 符号流），并在核心侧轮询 `busy/done`。
2. **执行装入代码**：装载落位后，把任务入口置入 ПР/PC，跑一段真实 103 程序，验证装入代码可执行。
3. **RTL 引擎模块**：`copy_engine.v` 与 C 原型一一对应；内存写口加 CPU/引擎二选一仲裁 mux；本阶段不做并发，装载期核心停住。
4. **重叠区策略**：源/目的重叠时的上移/下移方向，需在 RTL 化前确定。
5. **块目录/校验**：镜像 ID、入口 entry、类型、校验和作为第二阶段；本阶段仅做长度与边界检查。
