## 1. 本轮范围与边界

P0 三项为**上板 / FPGA 综合前必须解决**的阻塞项，本阶段定位仍是纯软件仿真闭环。本轮按"证据不足不硬上未验证链路、每个增量要有可回归出口"推进：

- 做静态综合可达性检查，暴露可综合性缺陷并修复；
- 对三项 P0 做事实 / 推断 / 未知三栏界定，定位根因与前置依赖；
- **不**改引擎 FSM 节拍、**不**换 BRAM 模型、**不**实现 Flash/ROM 与块目录（无板级对照、牵动全链路回归，留待上板阶段）。

### 3.2 yosys 静态结构检查（通过）

脚本：`work/regress/synth-core-top/struct.ys`（`read_verilog → hierarchy -top core_top → proc → opt → check → stat`，不走 ABC 优化）。源文件 = `work/ip_core/core/*.v`（8 个，排除 `.orig`）+ `work/rtl/mem_write_arbiter.v`。

结构统计（含子模块）：

| 指标 | 数值 |
|---|---|
| wires / wire bits | 977 / 4126 |
| cells | 599 |
| 触发器（$sdff/$sdffe/$dffe/$adffe/$adff） | 38 + 23 + 9 + 5 + 1 = **76** |
| 主存储 | 1 memory，**63488 bits**（= 2048 × 31，保留为 memory 原语未展开） |
| 子模块 | 8（arith_ctrl / arith_unit / io_unit / memory / operator / pulse_unit / select_reg / start_reg） |

`check` 无报错；无意外 latch、无组合环、无零位宽。仅两条提示：仲裁器小队列 `cpu_q` / `eng_q` 被替换为寄存器（小容量 FIFO 展开为 FF，符合预期）。

### 3.3 本轮修复的可综合性缺陷：`addr_r` 跨两块双驱动

**现象**：首次完整 `synth` 时 yosys 报 `multiple conflicting drivers for memory.addr_r[11:0] … [0]`。

**根因**：`work/ip_core/core/memory.v` 中同一寄存器 `addr_r` 被两个独立 `posedge clk` 时序块驱动：

- 写地址锁存块（原 85–93 行）：复位 / `do_mem_write && !cpu_hold` 时 `addr_r <= addr`；
- 读地址锁存块（原 107–109 行）：`do_mem_read` 时 `addr_r <= addr`。

跨块双驱动在 iverilog 仿真下被容忍（非阻塞赋值按块顺序覆盖），所以既有回归全绿；但综合判为冲突驱动，属不规范 RTL。

**修复**：拆成写 / 读两个独立地址寄存器，赋值条件与优先级保持不变：

- `addr_wr_r`：写路径锁存，`cpu_wr_addr = addr_wr_r`；
- `addr_rd_r`：读路径锁存，`read_data_r <= mem[addr_rd_r]`。

改动文件：仅 `work/ip_core/core/memory.v`。修复后重跑 yosys 结构检查，多驱动告警消除。

### 3.4 Gowin 厂商综合（卡在 RAM 推断）

命令：`synth.py --src <core 8 文件> mem_write_arbiter.v --top core_top --pn GW1NSR-LV4CQN48PC6/I5`。综合器走到 `Running inference` 阶段报错：

```
ERROR (IF0008): The number(63488) of DFF used to infer "mem" exceeds the
resource limit(3573) of current device(GW1NSR-LV4CQN48PC6/I5)
```

即主 RAM `mem[0:2047]`（2048×31 = 63488 bit）**没有被推断为 BSRAM/SSRAM 块 RAM**，而是被展开成 63488 个 DFF，超出器件 FF 总数。换更大的 9C 器件（6480 FF）仍装不下 63488 FF——只有正确推断为按 bit 容量计的块 RAM 才可行。

### 3.5 OSS yosys ABC 限制

完整 `synth`（含 ABC 优化）在大型 RAM 上 `Out of memory`（ABC fraig 阶段）：主 RAM 被展开进 ABC 网络后内存爆掉。这是 OSS 链在该规模下的工具限制；结构检查（proc/opt/check/stat）不经过 ABC，可正常完成静态核查。

### 3.6 P0-3 未出数项

- LUT / FF / ALU / BSRAM 利用率与 Fmax、Logic Level：**未取得**。前置条件是 P0-1 给出可被 BRAM 推断的 RAM 模型，使 Gowin 综合能越过 RAM 推断阶段。
- 时序收敛、P&R、位流：本阶段不涉及（P&R 仅 GUI，无 CLI）。

## 4. P0-1 RAM 读延迟模型：现状与根因

### 4.1 已核实事实

- **CPU 主读写路径已是同步一拍口径**（`memory.v`）：读在 `reading` 拍 `read_data_r <= mem[addr_rd_r]`，`read_finish_r` 跟随 `reading`；写经 `mem_write_arbiter` 授权后落数组，`write_finish_r <= grant_cpu`。该路径与 PU/AC/IO reply 握手闭环，回归全绿。
- **引擎 / ctrl / dbg 旁路为组合读**（`memory.v` 198–200 行）：
  ```verilog
  assign eng_rd_data  = mem[eng_rd_addr];
  assign ctrl_rd_data = mem[ctrl_rd_addr];
  assign dbg_rd_data  = mem[dbg_rd_addr];
  ```
- **引擎 FSM 按组合读节拍**（`work/rtl/copy_engine.v`）：`ST_FETCH` 态同拍 `latch_word_r <= rd_data`（185 行），下一拍进 `ST_WRITE`——即假设 FETCH 拍给地址、当拍数据有效。文件头注释（10–13 行）已标注该组合读假设，并写明上板挂真实 RAM 时需在引擎与 RAM 间补一级读缓冲、不改 FSM 节拍。
- **S011 原始模型**（`work/ip_core/include/S011HD1P_X32Y2D128.v`，备份 `memory_s011.v.orig`）：同步读写，`Q <= ram[A]` 一拍读出；含 8 片选译码（`addr[11:8]` 选片）与 BWEN 位掩码分位写（`addr[1:0]` 选字）。这些片选 / 位掩码边界在当前扁平数组行为模型中**未覆盖**。

### 4.2 综合侧根因链

1. 行为数组同时挂了 CPU 同步读端口与引擎/ctrl/dbg 组合读端口，多端口 + 组合读不符合主流综合器的同步读 BRAM 推断模板；
2. 综合器无法把数组映射为块 RAM，退回 DFF 阵列 → 63488 DFF（见 3.4）；
3. 即便推断为 BRAM，真实块 RAM 有一拍读延迟，而引擎 FSM 按组合读同拍锁存，直接上板会采样不到数据。

### 4.3 本轮未做与理由

- 未补读缓冲、未改引擎 FSM 节拍：读缓冲要配合 FSM 等待态调整，牵动 copy_engine 7 态 FSM 与全部引擎回归用例；当前无真实板 / BRAM 对照，属未验证链路，按偏好不硬改。
- 未替换为显例化 Gowin BSRAM 原语：需先定端口口径（单口/双口、位宽、字节使能）与引擎读缓冲方案，留待上板阶段。

### 4.4 落地前置（上板阶段）

1. 定 RAM 模型口径：同步读单/双口，CPU 主路径与引擎旁路统一到同步读；或显例化 Gowin BSRAM/SSRAM 原语，替换扁平行为数组。
2. 引擎侧补一级读缓冲，FSM 在 FETCH 后多等一拍对齐 BRAM 延迟（按 `copy_engine.v` 头注释既定方案，不改写主握手）。
3. 补齐 S011 片选 / 位掩码边界的定向用例；全量仿真回归 + Gowin 综合越过 RAM 推断阶段后复核时序与资源。
