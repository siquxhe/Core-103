# 4o · L4 候选 · 闲置位（bit31）利用方向评估：BRAM 奇偶校验 / 固件段写保护

> 关联：`4f-P0-2镜像目录与校验链路现状界定与方案设计.md` §5.4 镜像格式冻结口径、`4n-86-L4整链路综合资源与时序复核.md` 整链路基线、`4m-60-RAM读延迟模型与读缓冲回接闭环复核.md`；三方共用格式头 `image_format.h`。
> 口径：本报告为方向评估，**不改动现有 RTL / 打包器 / 模拟器**；结论区分已核实事实、合理推断、未知存疑。
> 触发：讨论 31 位数据字对齐 32 位 BRAM / NOR 档位后，闲置高位能否用一套简单电路承载校验位或写保护位。

## 1. 结论先行

- **先校正前提**：CPU 数据字 31 位（bit30 符号 + bit29:0 数值），31 位全有语义，**没有闲置的数值位**；真正预留恒 0 的是 32 位容器 / 总线之外的 **bit31**，以及 BRAM 对齐到 32 位档位时物理多出的那一列存储。
- **两个候选方向分属两层，不可压成一块通用电路**：
  - 方向 A（主存奇偶校验）落在 **BRAM / 总线层**，要先把整条 31 位总线扩到 32 位，穿透 CPU 拼拆、引擎、仲裁、ctrl、dbg、loader 落库全部端口，触及上游派生内核；
  - 方向 B（固件 / 数据段写保护）落在 **镜像 / 装载层**，段表 A 字已有 4 位预留标志域 `flags[30:27]`，可在不碰内核数据通路的前提下定义其中 1 位为只读保护位。
- **定级倾向**：A 暂缓（片上 BRAM 软错误边际收益低、改动面大、只检不纠且无错误处理通路）；B 列为 **L4 候选前置预留**——先在镜像格式层登记标志语义与 loader 解析扩展点，拦截电路待路线 B 接 NOR 时落地。

## 2. 调查事实台账

### 2.1 CPU 主存数据通路（已核实）

| 项 | 位宽 / 取值 | 出处 |
|---|---|---|
| 主存数组 `mem` | `[30:0]` 31 位 | `core/memory.v:71` |
| CPU 写拼字 | `{write_sign_from_ac, write_data_from_au[29:0]}` = 1 符号 + 30 数值 | `core/memory.v:30,32,82` |
| CPU 读回拆分 | `{read_sign_to_ac, read_data_to_au} = read_data_r` | `core/memory.v:220` |
| 算术单元数值寄存器 | `[29:0]` 30 位；加法 `val_sum[30:0]` | `core/arith_unit.v:40,41,44,45,59` |
| 引擎 / ctrl / dbg / 仲裁 / ram_model / 通路封装 | 总线全部 `[30:0]`，无 bit31 信号线 | `copy_engine.v:41,45`；`engine_ctrl.v:48,51,56`；`mem_write_arbiter.v:31,36,41`；`mem_ram_model.v:26,30`；`engine_mem_path.v:37,42,62,64` |

### 2.2 镜像容器格式（已核实，`image_format.h` 冻结口径）

- 容器为 32 位字、4 字节 / 字、小端；**数据字 bit31 预留=0，bit30 符号，bit29:0 数值（定点 1.30，符号-数值码）**（`image_format.h:5`）。
- 掩码：数值域 `IMG_VALUE_MASK=0x3fffffff`（30 位）；符号位 `IMG_SIGN_BIT=0x40000000`；校验和 `IMG_SUM_MASK=0x7fffffff`（mod 2^31，bit31 不参与）（`:33,34,37`）。
- 目录头字 1：N[11:0] / entry[23:12] / ver_algo[30:24]，bit31 未分配（`:46-54`）。
- 段表 A 字：dst[11:0] / off[23:12] / type[26:24] / **flags[30:27]**；flags 为 4 位预留标志域（`:57,62-72`）。
- 段表 B 字：len[11:0]，高位预留（`:74-76`）。
- 校验字：只比对低 31 位，bit31 不参与（`image_loader.v:181,183`；`image_format.h:82-84`）。
- 打包器当前 `flags` 恒传 0，4 位标志域未定义语义（`tape-converter/src_imagepack/main.c:211`）。

### 2.3 RTL loader 解析侧（已核实）

- 镜像数组 `img[31:0]` 32 位；写主存只取 `[30:0]`，bit31 丢弃（`image_loader.v:51,219`）。
- `sum_word = w[29:0] + w[30]`，w[31] 不参与累加（`:86-91`）。
- 头 / 段表位域解析用到 bit30 为止（`:131-156`）。

### 2.4 综合 / 外设现状（已核实 + 推断）

- 整核推断 8 块 SDPB BSRAM（synth-converged 资源报告）；当前为综合推断 BRAM，未显例化原语。
- **推断**：31 位宽数组综合到 BRAM 时，档位向上对齐到原生 32 位宽，物理多出第 32 列；网表加密、报告未明文位宽 / 深度，需未加密综合或 P&R 配置确认（见 §7 存疑）。
- 当前 `hardware_top` 只有按钮 / 开关 / 74LV 串行驱动，**无 NOR / Flash / SPI 外设接口**；路线 B 才把 `$readmemh` 文本源替换为 SPI NOR 字流，解析 / 校验逻辑不变（`image_loader.v:8-10`）。

## 3. "闲置位"辨析：两层不要混

| | BRAM / 总线层 | 镜像 / NOR 层 |
|---|---|---|
| 闲置来源 | 31 位 RTL 总线对齐到 32 位 BRAM 档位，物理多出第 32 根线 | 32 位容器字的 bit31（预留恒 0）；段表另有 flags[30:27] 预留 |
| RTL 是否已有该线 | 否，总线止于 `[30:0]` | 容器侧有（`img[31:0]`），落主存后丢失 |
| 复用是否触及内核 | 是，需扩总线穿透全部端口 | 否，只动格式定义 + loader 解析扩展点 |
| 改动面 | 大，覆盖上游派生件 `core_top.v` / `memory.v` | 小，格式位域预留 + 打包 / 装载两侧对称 |

## 4. 候选方向 A：主存每字奇偶校验位

### 4.1 电路骨架（预案，未实现）

- 写口：对 31 位数据做 XOR 树得 1 位 parity，随数据写入 BRAM 第 32 列。
- 读口：重算读出 31 位的 XOR，与存列比对；不一致置 `parity_error`。
- 落点：parity 列需独立于数据字 31 位；不能压在 bit30（符号位）。

### 4.2 收益

- 可检测单比特翻转（**仅检奇错，不纠错**）；DDR / ASIC 内存常用，FPGA 片上 BRAM 软错误场景边际收益有限。

### 4.3 成本与风险

- **总线扩宽**：必须先把 RTL 总线从 31 位扩到 32 位，穿透 memory 内部数组、CPU 拼拆口、引擎 / ctrl / dbg / 仲裁、loader 落库口；改动面覆盖上游派生件（`core_top.v` / `memory.v`，修改派生，NOTICE 已登记）。
- **只检不纠**：当前内核无错误中断 / 停机 / 重试通路，检出后处理策略是半截工程。
- **时序**：XOR 树进入读路径，影响读口关键路径。
- **资源**：每读口一份 XOR 树与比对逻辑；parity 列占 BRAM 第 32 列（32 位档位本就预留，是否额外增块为推断，待综合确认）。

### 4.4 判定

**暂缓，不入近期实施**。若上板后确有可靠性需求，优先在显例化 BSRAM 原语级挂 parity 或做整字冗余，不在当前综合推断形态下改 RTL 总线宽度。

## 5. 候选方向 B：固件 / 数据段写保护位

### 5.1 落点选择

| 粒度 | 载体 | 电路 | 成本 | 评价 |
|---|---|---|---|---|
| 段级（推荐） | 段表 A 字现成 `flags[30:27]` 取 1 位作只读标志 | 1 位标志 + 段地址区间比较（段表 dst / len 现成） | 低 | 与现有段表结构对齐，打包 / 装载两侧对称扩展 |
| 字级 | 镜像体每字 bit31 作保护位 | 主存只存 31 位，保护位另存 2048 位小位图（LUTRAM / 独立 BRAM 列） | 中高 | 粒度细但需额外存储列与位图同步维护，暂不推荐 |

### 5.2 电路骨架（预案，未实现）

- 格式：段表 flags 定义 1 位 `SEG_FLAG_RDONLY`（如 flags bit0）；打包器对只读段置位，其余段清 0。
- 装载：loader 解析段表时缓存每段保护标志与地址区间。
- 拦截：运行期 CPU / 引擎 / ctrl 写主存命中受保护段区间时，在仲裁写口统一拦截（或置违例标志 / 错误码）。
- 校验：保护标志位纳入校验和口径时需两侧同步（当前 `sum_word` 未覆盖 bit31 / flags，升级时复核）。

### 5.3 收益

- 无 MMU 的小核靠硬件位图 / 区间比较，防止固件、常量数据段被运行期误写；与内核算术通路解耦。
- NOR 自身有 WP# / 扇区锁，硬件拦截是装载后运行期的额外保险，不替代 NOR 物理写保护。

### 5.4 成本与风险

- 打包器（image-pack）、模拟器装载侧、RTL loader 三处格式头需对称更新（`image_format.h` 双份副本）。
- 拦截逻辑落在仲裁写口或 memory 写旁路，需覆盖 CPU / 引擎 / ctrl 三个写主。
- 路线 B 的 NOR 器件、数据宽度、寻址粒度未定；位域定义需前瞻兼容（24 位绝对字节偏移已预留扩段表第三字，见 `image_format.h:58-60`）。

### 5.5 判定

**列为 L4 候选前置预留**：现阶段只在格式层登记标志语义与 loader 解析扩展点，不实现拦截电路；待路线 B 接 NOR、上板阶段落地。

## 6. 方向对照矩阵

| 维度 | A 主存奇偶校验 | B 段写保护 |
|---|---|---|
| 所在层 | BRAM / 总线 | 镜像 / 装载 |
| 是否触及内核算术通路 | 是（扩 31→32 总线） | 否 |
| 现有预留位 | 无（BRAM 第 32 列为推断对齐出） | 有（flags[30:27] 4 位） |
| 电路复杂度 | XOR 树 + 比对 + 错误处理 | 标志缓存 + 区间比较 + 写口拦截 |
| 收益性质 | 可靠性检错 | 防误写保护 |
| 纠错 / 处置 | 只检不纠，缺处置通路 | 拦截即可，语义明确 |
| 改动面 | 大（内核派生链路） | 小（格式 + 装载侧） |
| 定级 | 暂缓 | L4 候选前置预留 |

## 7. 存疑 / 待确认

- 综合后 BRAM 实际配成 32 位宽还是切成多块窄宽（16×2 等）：报告未明文，网表加密；需未加密综合或 P&R 配置核实。
- 若未来扩总线，定点补码是否从「1 符号 + 30 数值」扩为「1 符号 + 31 数值」：属算术单元兼容决策，本轮未深挖 arith_unit 进位 / 移位语义。
- NOR 器件数据宽度、寻址粒度、WP / 扇区锁方式：路线 B 设计前需先定。
- 保护标志是否纳入校验和：升级镜像格式时需打包 / 装载 / RTL 三方复核口径。

## 8. 落地前置依赖（若后续启用）

- 方向 B：路线 B loader 可综合化（替换 `$readmemh`）；写口仲裁统一拦截点；`image_format.h` 双份同步；补只读段装载 / 违例 tb；回归基线不回退。
- 方向 A：显例化 BSRAM 原语定口径；错误处置通路（中断 / 停机 / 重试）；显例化后再评估 parity 列与读路径时序。
