# 4a · M-3 / 103 装机容量调研与片上 BRAM 改造方案

> 日期：2026-11-25 ｜ 阶段：P0-1 RAM 模型改造前置调研
> 口径：史料为二手/博物馆资料，分歧处并列标注；BRAM 块数、宽深档位为估算，最终以 Gowin 综合报告 `*_syn_rsc.xml` 为准。仿真 PASS 只覆盖已激励路径。

## 1. 调查目的与范围

弄清两件事：
1. M-3（苏联）与 103（中国仿制）历史上的**实际装机容量**是多少，指令/地址字段决定的**理论最大容量**是多少；
2. 在现有 Gowin FPGA 器件的实际 BRAM 特性约束下，把当前行为数组主存改造成可推断为块 RAM 的模型，给出分阶段改造方案。

调查材料：俄罗斯虚拟计算机博物馆 M-3 页面（英文/俄文）、IEEE Xplore 布达佩斯 M-3 技术特性附录、中科院/北大计算中心史料、当前 RTL（`memory.v`、`copy_engine.v`、`select_reg.v`）、Gowin 器件表 CSV。

## 2. 史料调研：实际装机容量

### 2.1 已核实事实（附来源）

**字长与数制**

- 定点二进制，**30 位绝对值 + 1 位符号**；IEEE 附录记为 "31 bits/word … 1 sign bit"，博物馆记 "30 binary places (in absolute value < 1) and a digit for number's sign"。
- 当前 RTL 口径一致：`reg [30:0] mem[...]`，31 位宽。

**指令格式（双地址，三方一致）**

- 6 位操作码 + 两个 **12 位地址**（地址以 4 位八进制表示）；博物馆、IEEE 附录、俄文教学资料相互印证。
- 位映射（教学资料口径）：bit0 保留；bits1–6 操作码；bits7–18 第一地址；bits19–30 第二地址。合计 1 + 6 + 12 + 12 = 31。

**装机容量（分阶段、来源存在分歧）**

| 阶段 / 机型 | 容量 | 字长口径 | 来源 |
|---|---|---|---|
| M-3 磁鼓早期 | 1 kWord（IEEE，后 1.6 kWord）；博物馆记磁鼓 **2048 字** | 31 位 | IEEE Xplore 附录；computer-museum.ru |
| M-3 磁芯操作存贮 | 1 kWord（IEEE）；博物馆记换**同容量**磁芯 | 31 位 | 同上 |
| M-3 扩存（第二存贮柜） | **翻倍到 4096 字** | 31 位 | computer-museum.ru |
| 103 磁鼓 | **1024 字** | 中文记 32 位 | 中科院、北大计算中心 |
| 103 磁芯改造 | **2048 字** | 中文记 32 位 | 北大计算中心大事记 |

### 2.2 合理推断

- 中文史料"字长 32 位"应为转述取整（含保留位/校验位口径差异）；一手俄文与 IEEE 口径均为 **31 位**，与当前 RTL 一致。
- 容量随改造阶段递增：早期磁鼓 1024 字 → 磁芯 2048 字；M-3 通过增加第二个存贮柜扩到 4096 字。1024 / 2048 / 4096 分别对应半柜、单柜、双柜档位。
- 磁鼓与磁芯同容量替换时，变的是存取速度（磁鼓 30 ops/s → 磁芯 1500–2500 ops/s），不是容量。

### 2.3 未知 / 存疑

- 103 机各批次磁芯究竟是 1024 还是 2048 字，中文源之间、中文与俄源之间不完全一致；缺少一手维修手册/备件清单佐证。
- M-3 双鼓 2×1600 字（IEEE）属后台缓冲存贮，与操作存贮口径不同，未计入主存容量。
- 历史上是否存在 4096 字以上的第三方改装，史料未载。

## 3. 理论最大容量推导

- 地址字段 **12 位**（`[11:0]`），选择寄存器 `reg_select` 同为 12 位；可寻址空间 = 2¹² = **4096 字**（地址 0–4095）。
- 该上限与博物馆"加第二存贮柜扩到 4096 字"吻合：**理论最大容量 = 4096 字**，12 位地址位宽正是为双柜满配预留。
- 当前 RTL 实现 `WORDS = 2048`，处于单柜磁芯档；地址总线已留 12 位，扩到 4096 字不需要改指令格式或地址通路。

### 容量折算（31 位字，按字节/Kb 双口径）

| 配置 | 位数 | Kb | 字节 | KiB |
|---|---|---|---|---|
| 1024 字（早期磁鼓） | 1024 × 31 = 31744 | 31 Kb | 3968 B | 3.875 KiB |
| 2048 字（单柜磁芯，当前基线） | 2048 × 31 = 63488 | 62 Kb | 7936 B | 7.75 KiB |
| 4096 字（双柜满配，理论上限） | 4096 × 31 = 126976 | 124 Kb | 15872 B | 15.5 KiB |

> 注意：这是**按字编址的主存**，不是 2KB 缓存；2048 字折字节已约 7.75 KiB。

## 4. 器件 BRAM 容量对照（Gowin 器件表 CSV）

| 候选器件 | 片上 RAM/BSRAM 量级 | 2048 字（62 Kb / 按 32 位宽 64 Kb） | 4096 字（124 Kb / 按 32 位宽 128 Kb） |
|---|---|---|---|
| GW1NZ-LV1QN48C6/I5 | Kb 级分布式 + 几十 Kb | 偏紧/不够 | 不可行 |
| GW1NSR-LV4CQN48PC6/I5 | 180 Kb 集成 RAM | 可行，有余量 | 偏紧（128/180 ≈ 71%），需综合复核 |
| GW1N/GW1NR-9C | 468 Kb BSRAM | 宽裕 | 宽裕 |

- 按通用 18 Kb/块粗估：2048×32 ≈ 64 Kb ≈ **4 块**；4096×32 ≈ 128 Kb ≈ **8 块**。块数为估算，实际宽深档位与拼块方式以综合报告为准。
- 准确 LUT/FF/BSRAM 分母以综合后 `*_syn_rsc.xml` 的 `T_` 总计为准。

## 5. 当前 RTL 存储口径（改造基线）

- 存储：`mem [0:WORDS-1]`，`WORDS=2048`，31 位宽（`memory.v:12,66`）。
- 写主两路：CPU 写主、引擎子系统（引擎搬运 + ctrl 状态镜像）写主，已经过 `mem_write_arbiter` 收敛为**单写口** `ram_wr_req/addr/data`，含背压 FIFO 与挂起保持。
- 读口四路：CPU 主读、引擎旁路读、ctrl 旁路读、dbg 调试读；当前引擎/ctrl/dbg 为**组合读**（`memory.v:200-202` `assign ... = mem[...]`）。
- CPU 主读写已是同步一拍口径：读在 `reading` 拍 `read_data_r <= mem[addr_rd_r]`；写经仲裁授权后落数组。
- 引擎 FSM 按组合读节拍：`ST_FETCH` 态同拍 `latch_word_r <= rd_data`（`copy_engine.v:185`），下一拍进 `ST_WRITE`——即假设 FETCH 拍给地址、当拍数据有效。
- 现状综合问题：行为数组多端口 + 组合读不符同步读 BRAM 推断模板，主 RAM 被展开为 63488 DFF，超器件 FF 上限（详见 3a 报告 §3.4）。

## 6. 目标 BRAM 模型的实际特性约束

1. **同步读延迟一拍**：块 RAM 给地址后，数据在下一拍输出；不存在组合读当拍有效。
2. **端口数有限**：单口（1 读 1 写）或双口（2 读 2 写）；现状四读口 + 两写主无法直挂单块 BRAM，必须收敛或复用。
3. **宽深可配、位宽拼块**：块 RAM 按固定容量成块，31/32 位宽通常需两块拼宽或用 32 位宽档位留 1 位；深度与位宽此消彼长。
4. **写后读口径**：同一周期写同一地址，读出是旧值还是新值需与现有行为模型对齐，避免回归假 PASS。
5. **推断模板敏感**：多端口、组合读、非标准复位写法都会让综合器退回分布式 RAM 或 DFF 阵列。

## 7. 改造方案

### 7.1 容量参数化

- `memory` 顶层保留 `WORDS` 参数，基线 2048，满配档 4096；地址位宽固定 12 位，不改指令/选择寄存器通路。
- 内部存储位宽对齐到 **32 位**（bit31 接地/预留），避免 31 位非标准宽在 BRAM 拼块时浪费容量；31 位接口在边界做截位/补位。
- 选型建议：2048 档 4C / 9C 均可；4096 档优先 **9C（468 Kb BSRAM）**，4C 仅在综合复核余量可接受时考虑。

### 7.2 端口收敛（核心难点）

**写口**：保持现有 `mem_write_arbiter` 不动——CPU 与引擎子系统已收敛成单写口，直接对接 BRAM 唯一写口；背压 FIFO、挂起保持、搬运优先/ctrl 顺延语义全部沿用。

**读口分级**：

- **CPU 主读**：接 BRAM 主读口。现有 `reading / read_data_r` 已是同步一拍口径，天然匹配同步 BRAM，不改 CPU 节拍。
- **引擎旁路读**：接 BRAM 第二读口（双口器件）。
- **ctrl / dbg 旁路读**：与引擎分时复用第二读口（使能仲裁 + 总线 mux）。依据：ctrl 命令块/状态镜像与 dbg 预填校验发生在装载/调试期，三者不同时读；若综合器仍推不进块 RAM，退路是把 ctrl/dbg 旁路映射到分布式 RAM（LUTRAM）或独立小寄存器镜像，dbg 仅复位预填/校验期使用。

**去掉组合读**：所有旁路读改为同步采样 BRAM 输出寄存器，删除 `assign eng_rd_data = mem[...]` 一类组合直读。

### 7.3 读延迟对齐（引擎 FSM）

- 真实 BRAM 同步读晚一拍：FETCH 拍给地址，下一拍数据才有效。
- 在 `ST_FETCH` 后增加一个等待拍（或一级读缓冲），下一拍再采样 BRAM 输出锁存到 `latch_word_r`，然后进 `ST_WRITE`。
- 按 `copy_engine.v` 头注释既定方案：**不改主握手语义**，只在 FSM 补等待态/读缓冲；CPU 主路径不动。
- 重叠区复制、并发、背压、满队等引擎套件需在改节拍后逐套回归对齐。

### 7.4 推断优先、显例化兜底两条路径

- **路径 A（行为推断优先）**：先把 `memory.v` 改写为单一同步读写数组、移除多组合读口，让综合器推断为 BSRAM；用 yosys 结构检查 + Gowin 综合观察是否进块 RAM、读资源是否从 DFF 阵列转为 BSRAM。
- **路径 B（显例化原语兜底）**：若行为推断仍失败，显例化 Gowin 块 RAM 原语（单口/双口，原语端口名以原语手册为准）；32 位宽两块拼宽，深度按 WORDS 档位映射。
- **仿真/综合双模型分层**：抽出存储内核层——iverilog 仿真用 `reg` 行为数组，综合用 BRAM 原语/推断模型，通过 `ifdef SYNTHESIS` 或配置参数切换；保证既有 iverilog 回归在仿真模型上继续跑通。

### 7.5 边界与定向用例补齐

- S011 片选译码（`addr[11:8]` 选片）、位掩码分位写（`addr[1:0]`）边界用例；
- 满配地址边界：0、2047/2048、4095 的读写；
- BRAM 写后读（同址同周期）口径用例；
- 引擎读延迟对齐后：重叠区方向、CPU/引擎并发、写背压满队、引擎端到端全套回归不回退；
- 4096 字参数档在目标器件上综合复核资源与 Fmax。

### 7.6 分阶段落地与回归出口

| 阶段 | 内容 | 回归出口 |
|---|---|---|
| 1 | `memory.v` 同步读改造，CPU 主路径单口化；仿真模型保持行为数组 | iverilog 全量回归（core-eb / IO 三例 / 九套引擎仲裁 / RTL 三档）保持绿 |
| 2 | 引擎旁路接第二读口 + 读缓冲/FSM 等拍；ctrl/dbg 分时复用或 LUTRAM 兜底 | engine-mem / engine-ctrl / move-cov / concur / engine-core 等引擎套件对齐 |
| 3 | Gowin 综合观察 BRAM 推断；出 LUT/FF/BSRAM 利用率与 Fmax；不进块 RAM 则显例化原语 | 综合报告 BSRAM 计数上升、FF 不再是 63488 DFF；时序 Level/Fmax 有读数 |
| 4 | 4096 字参数档综合复核，定选型器件 | 满配档资源余量（建议 Logic/FF 利用率 ≤ ~70%）与 Fmax 达标 |

## 8. 风险与待确认项

- **多端口推不进 BRAM**：退回分布式 RAM 或复制存储，容量/片数需重新估算；
- **31 位宽拼块**在小器件上占用块数偏多，4C 满配余量有限；
- **FSM 等拍改造**可能引入节拍回归，需逐套件对齐，不能一次改完全量；
- Gowin 块 RAM 原语的具体端口名、宽深档位、单/双口类型，实现阶段需查原语手册或综合网表确认（本机帮助文档为编译 qch，未解出）；
- 103 历史磁芯容量档位史料存在分歧，本方案以"2048 基线 / 4096 满配"为工程目标，不依赖历史容量考证结论。
