# 4p · L4 候选 · 配套高级语言子集 × FPU 协处理器 配套选型评估

> 关联：`02-现代类比与可行性评估.md` §2 高级语言适配（Fortran II 静态子集推演 / 不适配范式）、`04-FPU集成设想.md` §4.2 软件工具链清单与 §7 Z3/Z4 参照评估、`4h-装载器与固件叠加启动路线方案设计.md` 固件命令块握手链路、`指令集兼容性核对.md` 命令表与寄存器分工。
> 细化分文：语言侧见 `4q-语言子集-FortranII静态定点技术规格.md`；FPU 侧见 `4r-FPU协处理器技术规格细化.md`。
> 口径：本报告为方向评估，**不改动现有 RTL / 打包器 / 模拟器 / 编译器**；结论区分已核实事实、合理推断、未知存疑。
> 触发：RTL 量产复核等待期，评估"让人写程序更省力"的配套语言应取何种形态；中等程序规模；并澄清"解释器作为固件终端部件"的设想与既有台账判定之间的关系。

## 1. 结论先行

- **路线选定：一期走 Fortran II 风格的编译型静态定点子集**。宿主侧编译器把类 Fortran 源码投影成 103 机器码镜像，目标机纯执行，**无常驻解释器**。这与 `02` §2.2 既有推演一致，也最契合本机无栈、无调用、无间接寻址的硬件底座。
- **"解释型终端"暂缓**：`02` §2.3 已将 BASIC 解释型判为不适配，依据是解释器常驻体积 + 字符串/动态存储机制不足；该依据（无栈 / 无 call-ret / 2048 字）至今未变。终端交互入口（装载、启动、数值 I/O）与常驻语言解释器是两件事，前者现有 loader + 固件握手 + 单字 I/O 已部分覆盖，后者单列为远期可选。
- **语言层与 FPU 层是配套的两个 L4 候选**：语言是科学计算的表达层，FPU（04 路线甲，Zuse 风格自定义浮点）是浮点硬件层；编译器后端按浮点调用约定把浮点表达式投影成 FPU 命令块握手序列。**一期子集只做定点，浮点作为后端扩展点预留**，待 04 格式规范冻结后再接。
- **硬边界**：主核定点语义保真；无递归、无动态调用、无堆；子程序静态约定、不可重入；变量与数组静态分配。本报告不产生可综合 RTL，不进 iverilog 回归基线。

## 2. 背景与触发

### 2.1 需求定位（本轮明确）

| 维度 | 口径 |
|---|---|
| 语言目的 | 让人写程序更省力；现有 `.103` 为裸八进制机器码，近乎无人会手写 |
| 程序规模 | 中等程序：带循环、条件、子程序，非几十字算例 |
| 运行形态倾向 | 曾设想解释器作为固件里的"终端"部件；需对照既有台账判定重新校正 |

### 2.2 与既有台账判定的冲突校正

`02` §2.3 明确判不适配的范式含 **BASIC 解释型**，理由：解释器常驻 + 字符串/动态存储，规模与机制均不足。本轮复核否决依据是否仍成立：

- 硬件底座未变：无栈指针、无 CALL/RET、无间接寻址、无中断/定时器、主存 2048 字（扩 4096）——见 `指令集兼容性核对.md` 与 `02` §1.2。
- 固件装载/握手链路虽已闭环（4h/4i/4j），但只解决解释器"挂在哪一层"，**没有消除常驻体积与软栈机制这两个硬伤**。
- 结论：既有判定仍成立；解释型路线不进一期，若要复活须先按 §7 补专项评估。

## 3. 事实台账（第一手核对）

### 3.1 硬件底座（已核实）

| 项 | 现状 | 出处 |
|---|---|---|
| 数值模型 | 30 数值位 + 1 符号位，定点符号—数值码；bit31 保留 | `指令集兼容性核对.md` §2 |
| 指令格式 | 双地址：6 位操作码 + 2×12 位地址；无变址、无间接寻址 | 同上 |
| 累加器 | А/В/С/Д 四个；Д 为并行加法器与进位链，**非通用寄存器**；结果留存 В/С 供下条复用 | 同上 §2 |
| 主存 | 标配 2048 字；模拟器分配 4096 字为扩容上限；高位地址当前镜像低半区 | 同上 §5 |
| 控制流 | 仅无条件转移（24/64/74）、条件转移（34）；无 CALL/RET、无栈帧、无中断 | 同上 §3.3；`02` §1.2 |
| 算术 | 加/减/乘/除/逻辑乘；无其他复杂寻址 | 同上 §3.1 |
| I/O | 纸带读入一数 → M[c2]；打印 reg_c 一数；运行期按进制开关八/十进制 | `simulator/src_c/103.c` `do_input` / `do_output_reg_c` |

### 3.2 现有程序表达层（已核实）

- `.103` 文本为裸机器码：`八进制地址@ ±操作码 c1 c2`，数据区直接填数值字；`char2tape` 仅做纸带穿孔编码，**无符号汇编、无助记符、无标签**（`tape-converter/src_char2tape/main.c`）。
- `test-program-gen` 的 `helper.py` 以种子生成算例，是宿主侧代码生成雏形；现有 C 代码是宿主模拟器/引擎原型，**不是编译到目标机的产物**。

### 3.3 固件与握手链路（已核实）

- 启动链：loader 灌镜像 → 联锁释放核心 → 固件取指；运行期固件经 PU 写命令块 `2400..2403`，轮询 `2405 DONE`，写 `2407 ACK` 握手（`4h` §2.2 / §3.1）。
- 该轮询握手模型与 FPU 协处理器的"送操作数 → 轮询完成 → 取回结果"同构，是语言后端接浮点/引擎服务的现成范式。

### 3.4 既有语言判定（`02` §2）

| 判定 | 范式 | 理由 |
|---|---|---|
| 最适配 | Fortran II 风格静态定点科学计算子集 | 静态分配、无堆、无递归/动态调用、GOTO 为主、一维静态数组 |
| 不适配 | LISP | 动态堆、递归、链表/指针，无栈无堆 |
| 不适配 | Forth | 依赖栈与字典编译机制 |
| 不适配 | BASIC 解释型 | 解释器常驻 + 字符串/动态存储，规模与机制不足 |
| 不适配 | Java / Python 等 | 虚拟机、堆、自动内存管理、递归 |

## 4. 路线选型对照

| 维度 | 路线甲：Fortran II 编译型静态子集（一期推荐） | 路线乙：解释型终端（暂缓） | 路线丙：现代通用语言后端（排除） |
|---|---|---|---|
| 产物 | 宿主编译器 → 机器码镜像，目标机纯执行 | 解释器常驻固件，逐句 REPL 解释 | 类 C 完整编译 + 寄存器/栈帧分配 |
| 目标机占用 | 仅用户程序 + 静态变量/数组 + 少量运行库 | 解释器 + 符号表 + 软栈常驻 | 需栈帧、堆、调用约定全套 |
| 无栈/无调用适配 | 静态分配、静态调用约定，天然绕开 | 表达式/调用需软栈模拟，机制补得多 | 硬件支撑缺失，硬做得不偿失 |
| 交互性 | 无 REPL；改程序重新编译装载 | 即时交互调试 | — |
| 台账判定 | 最适配子集（02 §2.2） | 原判不适配（02 §2.3） | 不匹配 |
| 一期定级 | **L4 候选，先行做宿主原型** | 远期可选，需专项复活评估 | 不采用 |

## 5. 一期语言子集边界（建议）

### 5.1 支持项

- **变量**：标量静态分配到主存变量段；单字母或短名，编译期符号表映射到固定字地址。
- **表达式**：`+ - * /`、括号、整数/定点常量；一元取负。
- **控制流**：赋值 `LET`、条件 `IF … THEN`、无条件 `GOTO`、`GOSUB / RETURN`、`PRINT`（数值）、`INPUT`（数值）、`REM` 注释、`END`。
- **数组**：一维静态定长数组；元素每字，下标在编译期可定值时直接算绝对地址（见 §5.3 限制）。
- **子程序**：`GOSUB` 调用、`RETURN` 返回；返回地址存固定静态槽。

### 5.2 排除项（一期不做）

- 递归、可重入子程序、动态调用；堆与动态存储分配；动态数组。
- 字符串运算与文本串变量（`PRINT` 一期只出数值）。
- 浮点数（等 04 FPU 规范冻结后由后端扩展接入）。
- 浮点库、就近舍入、复数等高级类型。

### 5.3 静态调用约定与受限点

- **无 CALL/RET 硬件**：子程序调用编译为"保存返回地址到静态槽 → 无条件跳转子程序入口"；`RETURN` 从槽取回返回地址跳转。**不可重入**：同一子程序嵌套/并发调用会覆盖返回槽，一期禁止。
- **局部变量**：静态分配，不随调用帧压栈；子程序间共享变量须在源码层显式约定。
- **表达式求值**：本机无求值栈，借累加器 В/С 结果留存链（op1=2/3 复用上次结果）把表达式编译成累加器传送 + 算术序列；复杂表达式的临时值落静态临时槽。
- **数组非常量下标**：指令无变址/间接寻址，循环变量作下标时需运行期修改指令地址字（基址 + 偏移经算术改写）；此为本机编码难点，一期先支持常量下标，非常量下标列为存疑项（§8）。

## 6. 编译器投影骨架（宿主侧，预案未实现）

```
源码 (.fa 类 Fortran 文本)
  → 词法 / 语法解析
  → 静态分配：标量、数组、常量、临时槽、返回槽 → 主存区间
  → 代码生成：语句/表达式 → 双地址机器码序列（借累加器留存链）
  → 静态链接：子程序入口、GOTO/GOSUB 标签回填
  → .103 机器码文本 → image-pack 结构化镜像 → loader 装载
```

- 编译器与中间库都在**宿主 PC** 上，不占目标机主存；目标机只承载生成的程序段、常量段、变量/数组段与固定返回槽。
- 生成产物对齐现有 `.103` → `image-pack` → `image_loader` 链路，不另起装载通路。
- 可顺带先做 **L0 符号汇编层**（标签 + 助记符 + 常量伪指令）作为编译器后端产物与人读中间层；解释器/固件自身开发也可受益，不再手写裸八进制。

## 7. 与 FPU 协处理器的衔接

### 7.1 分层职责

| 层 | 职责 | 现状 |
|---|---|---|
| 语言前端 | 解析、静态分配、类型检查（定点） | 未启动 |
| 编译器后端（定点） | 表达式 → 定点机器码序列 | 未启动 |
| 编译器后端（浮点，预留） | 浮点表达式 → FPU 命令块握手序列 | 待 04 规范冻结 |
| FPU 硬件 | 指数/尾数双通路、舍入、特殊值、状态标志回写 | L4 候选，路线甲已选定 |

### 7.2 衔接接口（待冻结）

- **浮点调用约定**：操作数与结果在主存/协处理器间的传递协议（对应 04 §4.2）；复用命令块轮询握手模型：主核发操作数 → 轮询完成状态 → 取回结果与状态标志。
- **助记符映射**：汇编/宏层浮点算子到浮点指令编码的映射；编码空间与触发方式随 04 规范另定。
- **依赖顺序**：先冻结 04 格式规范（位域、偏置值、隐藏位、特殊值真值表、零/符号规则、十进制换算）与 Python 数值 oracle → 再定操作数传递约定与浮点指令编码 → 编译器后端接浮点通路。**定点子集先行，不等 FPU。**

### 7.3 边界

- FPU 是隔离协处理器，不参与主核节拍链；语言层不得假设浮点运算改了主核定点数语义（04 §2 / §5）。
- 浮点表达式一期不进子集语法；后端接口在设计时预留，避免规范冻结后返工。

## 8. 体积预算方法（P1 原型阶段实测反推）

### 8.1 主存区间划分（2048 字基线，4096 扩容上限）

| 区间 | 内容 | 分配方式 |
|---|---|---|
| 程序段 | 编译出的机器码指令序列 | 代码生成按条计数 |
| 常量段 | 源码常量、子程序返回槽 | 静态表 |
| 变量段 | 标量静态变量 | 每标量 1 字 |
| 数组段 | 一维定长数组元素 | 每元素 1 字 |
| 预留 | 运行库传送/IO 桩、临时槽 | 固定小槽位 |

### 8.2 估算口径

- 代码体积：按语句/表达式编译出的机器码条数 × 字数；P1 原型用中等算例实测代码条数，反推单条语句平均码长。
- 数据体积：标量数 + 数组元素数 + 临时槽/返回槽数，每字 1 个 31 位字。
- **判据**：中等程序若压不进 2048 字，依赖 4096 扩容区；高位地址译码与镜像低半区口径需在扩容设计时明确（`指令集兼容性核对.md` §5）。
- 编译器本身、符号表、解析器不占目标机主存，不计入上述预算。

## 9. 风险与存疑

| 项 | 性质 | 说明 / 待核 |
|---|---|---|
| 非常量下标数组寻址 | 存疑 | 无变址/间接，循环下标需运行期改写指令地址字；编码可行性与码长待 P1 原型验证 |
| 可重入边界 | 限制 | 一期子程序不可重入；共享/重入需求出现时需补软栈或静态槽复制，属路线乙议题 |
| 中等程序规模上限 | 存疑 | 单程序实际字数上限需 P1 原型实测反推，再判断 2048 是否够 |
| 字符/文本 I/O | 前置依赖 | 终端式字符行输入、字符串输出依赖路线 B 串口/面板字符通路；现有 I/O 只到单字数 |
| 解释型复活条件 | 远期 | 若重启路线乙，须先补：解释器字占用体积预算、软栈深度与布局、字符行 I/O 通路、字符串存储方案；并推翻 02 §2.3 对应判定 |
| 定点定标 | 口径 | 定点小数定标（乘 `>>30`、除 `<<30`）沿用原机算法规约；浮点不继承该定标（04 §3） |

## 10. 落地分期与前置依赖

| 阶段 | 目标 | 产出 | 前置依赖 |
|---|---|---|---|
| P1 宿主原型 | 定点标量 + 一维静态数组解析/分配/代码生成；模拟器跑通中等算例 | 编译器前端 + 定点后端原型；体积/码长实测数据 | 不依赖 RTL；对接现有 `.103`/镜像链路 |
| P2 代码生成打磨 | 表达式累加器链、子程序静态槽、标签回填、常量下标数组；接装载链路 | 可生成可装载镜像的定点子集编译器 | P1 算例通过 |
| P3 浮点后端 | 浮点表达式 → FPU 握手序列；接浮点 oracle 对拍 | 浮点后端 + 调用约定落地 | 04 格式规范/oracle 冻结；FPU 通路就绪 |
| 可选 L0 | 符号汇编层（标签/助记符/伪指令） | 人读中间层 + 固件开发工具 | 随 P1/P2 顺带落地 |

**护栏**：各阶段产物不破坏现有 17 PASS 冻结基线与镜像 MD5 基线；语言/FPU 候选均不进当前回归基线。

## 11. 与既有台账关系

- 本报告仅评估方向与子集边界，不产生可综合 RTL，不改动既有打包器/模拟器/RTL。
- 对应 00 盘点 §5 开放项新增一条 L4 候选：配套语言子集（Fortran II 编译型静态定点），与 FPU 候选（04）配套登记；定点先行，浮点后端预留。
- 与 `02` §2 推演一致并更新口径：补接现有固件握手链路、I/O 现状与 L4 节奏；`02` 不适配范式判定维持不变。
- 选型结论的工程细化拆分到两份分文：语言子集规格 `4q`，FPU 协处理器规格 `4r`；本综合报告只保留选型对照、边界与分期定位。
