## 二、#83 三段背靠背编排（八进制）

### 2.1 段定义（`fw_l3c.seg`）

| 段 | 类型 | 目的地址 | 起 → 止 |
|---|---|---|---|
| 程序段 | 0 | `0000` | `0000..0033` |
| 常量段 | 1 | `2000` | `2000..2013` |
| 源数据段 | 1 | `1000` | `1000..1007` |

### 2.2 三段搬运

| 段 | SRC → DST | LEN | 源数据（十进制） | 目的区回读 |
|---|---|---|---|---|
| 段1 | `1000 → 3000` | 3 | 3 / 4 / 5 | `3000/3001/3002 = 3/4/5` |
| 段2 | `1003 → 3010` | 3 | 6 / 7 / 8 | `3010/3011/3012 = 6/7/8` |
| 段3 | `1006 → 3020` | 2 | 9 / 10 | `3020/3021 = 9/10` |

每段节拍：`05` 写 SRC(2400)/DST(2401)/LEN(2402)/GO(2403) → 轮询 2405 DONE=1 → `05` 写 2407 ACK → ctrl 自清、引擎回 IDLE。三段共用同一轮询骨架（b=DONE；c=b−1；负回环、非负往下）。

### 2.3 两个硬约束（踩坑记录）

- **103 无变址/间接寻址**：直接双地址寻址，多段参数不能做索引循环，只能在常量区按固定地址逐段展开（段2 参数 `2006/2007/2010`，段3 参数 `2011/2012/2013`）。
- **地址/数值均按八进制解析**：`.103` 与 `.seg` 的地址、数值走 `strtoul(base 8)`，八进制位不得含 8/9；十进制 8/9/10 须写成八进制 `10/11/12`（源数据 `1005=10, 1006=11, 1007=12`）。常量段区间若跨过含 8 的槽位（如 `2018`）会报"段源起地址大于源止地址"，须避开。

### 2.4 判据（12 项）

`entry=0000`；段1 三字 `3/4/5`；段2 三字 `6/7/8`；段3 两字 `9/10`；引擎回 `IDLE`（state=0）；ACK 镜像自清=0；DONE 镜像自清=0。

## 三、#84 仲裁器单元级加压

### 3.1 既有覆盖与本轮缺口

- `tb_cpu_eng_concur` 在集成层已覆盖：引擎搬运期间 CPU 并发写不丢字/不饥饿/授权互斥/目的区源区不被干扰（基线 `CPU-ENG CONCURRENCY PASS`）。
- `tb_engine_backpressure` 覆盖引擎侧背靠背/边界错误。
- 缺口：**仲裁器单元级**的双主竞争、轮转对称、FIFO 满队背压直观测无专门用例。本轮 `tb_arb_concur` 直接例化 `mem_write_arbiter`（FIFO_DEPTH=4），内部挂简易 RAM 模型。

### 3.2 阶段 A：并发 + 不丢 + 轮转公平

双主各 16 笔，地址错开（CPU `0..15` / 引擎 `16..31`），满队拍重试。编码：CPU 高位置 1、引擎高位置 0，低 5 位为序号。

DIAG：`cpu_in=16 eng_in=16 gc=16 ge=16 wr_total=32`。

判据：
- **授权互斥**：`grant_cpu` 与 `grant_eng` 永不同拍（双待授权即记 FAIL）；
- **不丢写**：CPU 区 0..15、引擎区 16..31 逐字落位且编码正确；
- **公平**：两主授权计数对称（`gc=ge=16`，差 ≤1），无饥饿。

### 3.3 阶段 B：并发灌满载队背压

双主全速并发灌 `BURST=12` 拍。机理：仲裁器出队只要队列非空就 grant、无 RAM 背压输入；单主直通每拍出队、队列不堆积，**只有双主竞争才净堆积**（每拍总入队 2、总出队 1）。

DIAG：`b_cpu_in=9 b_eng_in=9 stall_seen=1`。

判据（收敛到稳健可证口径）：
- **B1 背压可达**：并发灌入期间观测到 `cpu_full/eng_full`（stall）置位；
- **B2/B3 编码自洽**：CPU 区 `40..51`、引擎区 `60..71` 落位字若非 0，必须来源标记与序号匹配；未落位（0）槽位不判 FAIL。

### 3.4 遗留边界（单独立项 #87）

阶段 B 诊断轨迹显示：满队拍拒入与出队同拍发生，高压排空时队尾一笔（`cpu[11]`，addr 51，期望 `code(1,11)`）排空后未落 RAM。根因未定位——RTL FIFO `wp/rp` 指针回绕/排空轮转饿死，还是 tb 在满队边缘拍对 `!cpu_full` 采样导致 present 集合误标，本轮未下结论，**未改 RTL**。阶段 B 判据已不据此强判满队不丢；该边界留待 SymbiYosys/sby 形式验证（不丢字、指针回绕、无双授权不变量），定位后若属 RTL 缺陷再修并补回归。
