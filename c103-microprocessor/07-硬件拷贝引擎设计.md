# 07 硬件拷贝引擎设计

> 路线决策：外设采用**硬件拷贝引擎**——103 核心输入地址信息，引擎自动完成程序块加载。本设计基于 `core_top.v` / `io_unit.v` / `memory_fpga.v` 现有接口核实。

## 1. 现有接口硬约束（RTL 核实）

| 通路 | 现状 | 对引擎设计的约束 |
|---|---|---|
| 对外设备口 | 5 位双向握手：输入 `rdy/val`，输出 `rdy/ack`；io_unit 内移位拼装/拆解 31 位字 | 核心对外传数只能走串行符号流，不能一次甩一个 31 位字给外设 |
| 内存写地址 | 来自 select_reg 的 `sel_value`（12 位） | 当前只有 CPU 一个写主 |
| 内存写数据 | 来自 arith_unit（符号位 + 30 位数值） | 引擎直写内存需自备 31 位写数据通路 |
| 写使能 | 来自 io_unit 或面板脉冲 | 新增引擎写口需简单仲裁 |
| 地址空间 | 12 位，实际 BRAM 用 11 位 → 2048 字 | 多任务 + 镜像目录需先扩 RAM |

## 2. 两条接入路线对比

### 路线 A：复用现有输入握手（引擎假扮纸带机）

- 引擎挂现有 `dev_input` 口，按 io_unit 协议吐符号：选址符定 c2 → 逐位数字 → 写入符；
- 核心译码/内存通路零改动；
- 缺点：逐位串行、地址反复走选址协议，块搬运效率低；本质是"高速纸带机"，无块拷贝能力；受现有 io_unit FSM 节拍与缺陷牵制。
- **定位**：最小改动备选，不作为块拷贝主方案。

### 路线 B：引擎作为第二存储主，直连内存写口（推荐）

```
Flash/ROM 镜像区 ──► [拷贝引擎 FSM] ──► 写仲裁 ──► 内存写口(地址/31位数据/写脉冲)
                          ▲                                  ▲
                          │ 命令/状态寄存器                    │ 现有 CPU 写通路
                          │                                  │
                核心经输出口下发参数                   select_reg/arith_unit
```

- 引擎自带源地址、目的地址、长度计数器和 31 位写数据寄存器；
- 内存写口加二选一仲裁：CPU 写 / 引擎写；
- 本档先不做并发：核心在装载点停住，引擎独占写口，完成握手后核心再跑；
- 命令参数仍从现有输出口串行下发（复用 5 位符号流），批量搬运阶段挪到硬件。

## 3. 命令/状态寄存器

| 寄存器 | 位宽 | 含义 | 谁写 |
|---|---|---|---|
| `src` | 12 bit | Flash/ROM 镜像区源地址（块目录中的块偏移） | 核心写 |
| `dst` | 12 bit | RAM 任务区目的地址（装载原点） | 核心写 |
| `len` | 12 bit | 待搬字数 | 核心写 |
| `go` | 1 | 启动拷贝（脉冲） | 核心写 |
| `busy` | 1 | 引擎搬运中 | 引擎置 |
| `done` | 1 | 本块完成（握手清除） | 引擎置 |
| `err` | 若干位 | 越界 / 校验错 / 长度非法 | 引擎置 |
| `entry`（可选） | 12 bit | 从块头解析出的任务入口，供 dispatcher 建上下文 | 引擎置 |

## 4. 块目录与镜像格式（Flash 内固定布局）

```
块目录项(每项固定长度):
  镜像ID | 装载原点 dst | 字数 len | 入口 entry | 类型(码/数据) | 校验 | 标志
镜像体: 连续 31 位字 ...
```

- 绝对地址约定：任务镜像按固定原点链接，引擎原样落位，不做重定位；
- 校验可选：第一阶段做长度/地址边界检查，校验和作为第二阶段。

## 5. 引擎 FSM 状态定义

| 状态 | 动作 | 转出条件 |
|---|---|---|
| `IDLE` | 复位态，busy=0，等待 `go` | 收到 `go` 且参数合法 → `ARM` |
| `ARM` | 锁存 src/dst/len，边界检查 | 合法 → `FETCH`；非法 → `ERR` |
| `FETCH` | 从 Flash/ROM 读出一个 31 位字 | 读出就绪 → `WRITE` |
| `WRITE` | 经仲裁写入 RAM[dst]，dst++、计数器-- | 写完成 → `CHECK` |
| `CHECK` | `len==0`？ | 是 → `DONE`；否 → `FETCH` |
| `DONE` | 置 done，entry 寄存器更新 | 核心清 done → `IDLE` |
| `ERR` | 置 err，停在错误态待核心复位 | 核心清错误 → `IDLE` |

**复位要求**：`resetn` 有效时所有寄存器与状态显式回到 `IDLE` 位；不沿用 io_unit 现有 one-hot 复位缺陷写法（Issue #1）。

## 6. 与协作调度器的配合流程

1. 控制台常驻 ROM，上电后显示任务目录（引擎按 ID 读块目录）；
2. 核心向引擎寄存器写 `src/dst/len`，发 `go`；
3. 核心轮询 `busy`，引擎独占内存写口搬完整块；
4. `done` 后核心把任务入口、上下文槽登记进静态任务表；
5. dispatcher 按任务表轮询切换；引擎只在装载期使用，运行期不介入。

职责划分：引擎负责**批量装弹**，调度器负责**轮流击发**。

## 7. 落地顺序与验证

1. **C 模拟器先加引擎行为模型**：在 `103.c` 旁加 copy-engine 模型（src/dst/len/go/done），软件侧先跑通装载协议与调度协议；
2. **RTL 引擎模块**：新写 `copy_engine.v`，FSM 按第 5 节；内存写口加仲裁 mux；
3. **存储扩址**：2048 字装不下控制台 + 多任务 + 镜像目录，软核目标先扩到 4K–8K 字，2048 字留兼容模式；
4. **Flash 模型**：Verilator 侧挂行为 ROM/Flash 模型，灌入固定镜像；
5. **回归锁**：现有 17 PASS 基线不动，新增引擎装载用例（单块装载、越界报错、多任务依次装入）；
6. **自检项**：FSM 复位回 IDLE、`done` 握手清除、长度递减到零精确停止。

## 8. 边界

- 不做中断驱动 DMA：装载由核心主动发起、轮询完成；
- 不做并发读写：搬运期间核心停在装载点；
- 不改内核译码/节拍/指令集；
- 引擎是外设，核心仍为原 103 数据通路。
